## Главные мысли

### Базовые шаблоны
1. **Шаблоны** — способ написать код один раз для всех типов. `template <typename T>` говорит компилятору: "T — это любой тип, подставь его при использовании."
2. **Инстанцирование** — процесс генерации конкретного кода из шаблона. Когда пишу `Stack<int>`, компилятор создаёт отдельную версию класса для `int`. Для `Stack<std::string>` — другую версию.
3. **Шаблонные функции** требуют `template <typename T>` перед каждой функцией, потому что каждая функция — отдельная сущность со своим шаблонным параметром.

### Продвинутые шаблоны
4. **Шаблоны с несколькими параметрами**: `template<typename T1, typename T2>` позволяет создавать классы с разными типами (как `std::map<std::string, int>`).
5. **Приоритет специализации**: компилятор сначала ищет точное совпадение (специализацию `template<>`), если не нашёл — использует основной шаблон. Более специфичная версия имеет приоритет.
6. **`if constexpr`** (C++17): условная компиляция внутри шаблонов. Условие проверяется на этапе компиляции, а не выполнения. Позволяет добавить логику, зависящую от типов, без создания отдельных специализаций.
7. **Специализация != Наследование**: это не иерархия, а правило приоритета "более специфичная версия побеждает".

### Связь с STL
8. Все контейнеры STL (`vector`, `map`, `pair`) — это шаблоны. Когда я пишу `std::vector<int>`, компилятор генерирует отдельный класс специально для `int`.

## Ошибки и инсайты
- **Ошибка:** Пытался бросать исключения через `return std::runtime_error()`. Нужно использовать `throw std::runtime_error("message")`.
- **Инсайт:** `data_.back()` — безопасный способ получить последний элемент вектора. `data_[data_.size()-1]` тоже работает, но менее читаемо.
- **Инсайт:** Специализация шаблонов работает как перегрузка функций — компилятор выбирает наиболее специфичную версию для данного набора типов.
